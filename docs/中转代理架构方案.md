# 中转代理架构方案

## 1. 方案状态

本文是 GoYou“管理服务器承载中转流量”方案的设计记录。

当前实际部署进度见：[中转代理部署进度.md](./中转代理部署进度.md)。管理 API、管理后台、两端 sing-box、SSH 反向隧道和 relay 计量适配器已经完成基础部署；新租约使用独立凭据和动态端口，旧固定端口仅用于迁移兼容。

目标架构是：

```text
GoYou
    │ HTTPS 登录、获取代理租约
    ▼
管理服务器
    ├── 管理 API（FastAPI，推荐）
    └── sing-box 中转节点
            │ 服务器间隧道
            ▼
        真正的代理服务器
            └── sing-box 出口节点
                    │
                    ▼
                 GitHub/互联网
```

管理服务器不需要直接访问 GitHub。它只需要能够通过服务器间隧道访问真正的代理服务器。

## 2. 设计目标

- 用户必须登录后才能获取代理租约。
- 客户端只连接管理服务器，不直接暴露真实代理服务器地址。
- 管理服务器承载客户端代理流量，并把流量转发到真正的代理服务器。
- sing-box 和管理 API 均使用 Docker 部署。
- 后续可以增加、修改、禁用多个真实代理节点。
- 用户凭据、节点凭据和服务器间隧道凭据相互隔离。

## 3. 流量路径

```text
客户端本地应用
    ↓ 127.0.0.1:7890
GoYou 内置/启动 sing-box 客户端
    ↓ Shadowsocks 或其他代理协议
管理服务器 sing-box（中转入口）
    ↓ SOCKS outbound
WireGuard 或 SSH 反向隧道
    ↓
真实代理服务器 sing-box（出口）
    ↓ direct outbound
目标网站
```

管理服务器上的 sing-box 负责接收客户端连接并转发；真实代理服务器上的 sing-box 只负责最终访问互联网。

## 4. 管理服务器容器

开发阶段建议最少包含以下容器：

| 容器 | 职责 |
|---|---|
| `api` | 登录、用户、设备、代理租约、节点管理 API |
| `relay` | 管理服务器上的 sing-box 中转入口 |
| `tunnel` | WireGuard 或 SSH 反向隧道维护 |
| `db` | 开发阶段可使用 SQLite；用户量增加后切换 PostgreSQL |
| `gateway` | 可选，用于 HTTPS、限流和反向代理，例如 Caddy |

真实代理服务器最少包含：

| 容器 | 职责 |
|---|---|
| `sing-box-egress` | 接收管理服务器转发的流量并直接访问互联网 |
| `node-agent` 或 `tunnel` | 主动连接管理服务器，维持隧道并接收节点配置 |

真实代理服务器不需要暴露公网代理端口，最好只通过服务器间隧道访问。

## 5. 服务器间隧道选择

### 开发阶段：SSH 反向隧道

真实代理服务器主动连接管理服务器，并在管理服务器上暴露一个仅本机可访问的端口。管理服务器的 sing-box 将 outbound 指向该端口。

优点：部署快、排查简单，可以复用现有 SSH 基础设施。

要求：

- 使用专用的服务器间 SSH 账号和密钥；
- 私钥只放在服务器端，不进入 GoYou；
- 使用非 root 账号；
- 限制端口转发和登录权限；
- 使用 systemd、autossh 或专用 tunnel 容器自动重连；
- 固定并校验管理服务器主机指纹。

### 生产阶段：WireGuard

管理服务器和真实代理服务器建立私有地址，例如 `10.20.0.1` 与 `10.20.0.2`。管理服务器 sing-box 直接通过私有地址访问出口节点。

WireGuard 通常比 SSH 反向隧道更适合持续的大流量转发，延迟和资源开销也更低。WireGuard 仍然需要机器密钥，但这些密钥属于服务器之间的基础设施，不是用户凭据。

## 6. 账号和代理租约

客户端不能因为登录成功就永久获得一个共享代理密码。建议使用短期租约：

```text
POST /v1/auth/login
    ↓
POST /v1/proxy/lease
    ↓
返回管理服务器的 sing-box 地址、端口和短期凭据
    ↓
GoYou 启动本地代理
    ↓
租约到期前调用 /v1/proxy/lease/refresh
```

建议接口：

```text
POST /v1/auth/login
POST /v1/auth/refresh
POST /v1/auth/logout
GET  /v1/me
POST /v1/devices/register
POST /v1/proxy/lease
POST /v1/proxy/lease/refresh
POST /v1/devices/revoke
GET  /v1/nodes/health
```

每个租约至少包含：

- 用户 ID；
- 设备 ID；
- 使用的中转节点；
- 单独的代理凭据；
- 创建时间和过期时间；
- 带宽、连接数或流量限制；
- 撤销状态。

管理服务器上的 sing-box 需要支持按用户或按租约更新入口凭据。开发阶段可以通过重新生成配置并平滑重载实现，后续再接入动态配置机制。

## 7. FastAPI 与 Hyperf 选择

本项目建议第一版使用 FastAPI：

| 对比项 | FastAPI | Hyperf |
|---|---|---|
| 开发速度 | 快，适合快速验证 API | 需要 PHP/Swoole 运行环境 |
| 资源占用 | 单 worker 足够轻量 | 常驻进程也较轻量 |
| 异步和 WebSocket | 原生支持 | 原生支持 |
| 管理后台生态 | Pydantic、SQLAlchemy、Alembic | Laravel/Hyperf 生态更完整 |
| 适合当前项目 | 是，当前没有 PHP 后端约束 | 团队已有 PHP 基础设施时更合适 |

硬件瓶颈主要会出现在 sing-box 的带宽和加密转发上，而不是登录 API。低用户量时，管理服务器可以从以下规格开始：

- 1 vCPU；
- 512 MB～1 GB 内存；
- SQLite 数据库；
- API 单 worker；
- sing-box 根据带宽再单独扩容。

如果团队已经有成熟的 Hyperf、PHP 部署和后台代码，则可以选择 Hyperf；否则 FastAPI 更适合先完成方案验证。

## 8. Docker 部署边界

开发阶段建议：

- 管理 API、relay、数据库放在同一个 Docker Compose 项目；
- 真实代理服务器使用另一个 Compose 项目；
- 两端通过 SSH 反向隧道连接；
- 配置和数据库使用 Docker volume；
- 只开放管理 API 和中转入口的必要端口；
- 不把 sing-box 密码写入镜像或 Git 仓库。

生产阶段再考虑：

- SSH 隧道替换为 WireGuard；
- SQLite 替换为 PostgreSQL；
- 增加 Caddy/Nginx、限流、监控和日志；
- 管理 API 与 relay 分离部署；
- 增加多个真实代理节点和节点故障转移。

## 9. 安全要求

- 所有管理 API 必须使用 HTTPS；
- access token 使用短过期时间，refresh token 轮换；
- token 和代理密码存储在客户端系统钥匙串，不写入明文 JSON；
- 用户密码服务端只保存 Argon2id 或 bcrypt 哈希；
- 服务器间凭据与用户代理凭据分开；
- sing-box、API、tunnel 均使用非 root 用户运行；
- 不开放 sing-box 管理 API 到公网；
- 对账号、设备、代理租约做撤销和审计；
- 管理服务器只做转发，不解密 HTTPS 目标内容，但仍会看到连接目标和流量元数据；
- 对中转入口做带宽、连接数和账号级限流，避免成为开放代理。

## 10. 实施顺序

1. 使用 FastAPI、SQLite 和 Docker 完成登录 API。
2. 增加用户、设备、代理租约模型。
3. 在真实代理服务器部署 sing-box 出口节点。
4. 使用 SSH 反向隧道打通管理服务器到出口节点的链路。
5. 在管理服务器部署 sing-box 中转入口。
6. 让 GoYou 登录后获取租约并启动本地 sing-box。（客户端代码已接入，发行包仍需提供 sing-box 可执行文件。）
7. 接入现有 `127.0.0.1:7890` 系统代理和 GitHub 诊断逻辑。
8. 增加节点健康检查、租约刷新和撤销。
9. 将 SSH 反向隧道替换为 WireGuard。
10. 根据流量和用户量决定是否拆分 API、relay 和数据库。

## 11. 当前结论

该中转架构可行。推荐采用“FastAPI 控制面 + 管理服务器 sing-box 中转 + 真实代理服务器 sing-box 出口”的 Docker 化方案。

开发阶段使用 SSH 反向隧道降低部署复杂度；生产阶段使用 WireGuard 或专用节点 Agent。SSH 私钥只用于服务器间通信，不再要求最终用户向 GoYou 提供 SSH 私钥证书。
