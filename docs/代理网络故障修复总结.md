# 代理网络故障修复总结

## 1. 故障概述

2026 年 9 月 16 日，macOS 开启 GoYou 代理后，浏览器无法访问外网。关闭代理后网络正常，直接执行 `ping` 检查管理域名也正常。

自动网络诊断结果如下：

- 本地代理进程：运行中
- 本地 SOCKS 端口：已监听
- 系统代理：已启用
- GitHub、Google：均不可达
- 错误：`error sending request for url (...)`

## 2. 定位过程

依次检查了客户端本地代理、上游 relay 和服务器动态租约配置：

1. 确认客户端的 sing-box 正在监听 `127.0.0.1:7890`。
2. 通过本机 SOCKS5 代理访问 GitHub 和 Google，均返回 SOCKS5 `general failure`。
3. 直接检查当前租约对应的上游端口，发现连接被拒绝。
4. 检查服务器 relay 配置，发现两个有效租约同时使用了 `30003` 端口。
5. relay 内的 sing-box 因重复监听端口启动失败，导致客户端虽然保留本地监听端口，但无法向上游转发流量。

## 3. 根本原因

租约端口分配数据中存在历史重复记录。relay 计量适配器将重复端口写入 sing-box 配置后，sing-box 由于端口绑定冲突退出，客户端继续启用系统代理，从而造成浏览器所有请求都被转发到一个不可用的本地代理。

## 4. 已完成的修复

### 4.1 生产环境修复

- 将冲突租约迁移到空闲端口，保留当前使用中的租约端口。
- 重启并重建管理 API 和 relay 容器。
- 确认 relay 动态配置中的端口均唯一。
- 为数据库保留了修复前备份，便于必要时回滚。

### 4.2 服务端防护

修改 `management-api/app/main.py`：

- 服务启动时清理已过期、已撤销和非法的租约端口。
- 自动修复历史重复端口。
- 增加 relay 端口唯一索引。
- 刷新租约时检测端口冲突并自动重新分配。
- 分配新端口前释放失效租约占用的端口。

### 4.3 relay 防护

修改 `infra/relay/metering/metering_adapter.py`：

- 生成 sing-box 配置时检测重复端口。
- 遇到脏数据时跳过后续重复项，避免整个 relay 进程因端口冲突退出。

### 4.4 客户端防护

修改 `src-tauri/src/commands/goyou.rs`：

- 启用代理前先检查上游 relay TCP 端口是否可达。
- sing-box 启动后执行 SOCKS5 握手和实际目标连接测试。
- 上游不可用或握手失败时，不启用 macOS 系统代理，避免浏览器整体断网。

## 5. 验证结果

生产 relay 重启后进行了多次验证：

- 通过本地 SOCKS5 代理访问 GitHub：HTTP `200`
- 通过本地 SOCKS5 代理访问 Google：HTTP `204`
- 管理 API 健康检查：返回 `{"status":"ok"}`
- relay sing-box 进程：正常运行
- 活跃租约端口：无重复

本地代码检查结果：

- `cargo fmt --check`：通过
- `cargo check --manifest-path src-tauri/Cargo.toml`：通过
- `cargo check --target x86_64-apple-darwin`：通过
- Python 文件语法检查：通过
- `git diff --check`：通过

## 6. 后续建议

本节建议已按以下结果整改：

### 6.1 发布包含客户端上游预检逻辑的新版本

- 客户端版本已提升至 `1.0.39`。
- `goyou.rs` 在启用系统代理前检查上游 relay TCP 端口；sing-box 启动后再执行 SOCKS5 握手和实际目标连接测试。
- 预检失败时不会启用 macOS 系统代理，避免浏览器被切换到不可用的本地代理。
- 本地 `.app` 和 `GoYou.app.tar.gz` 构建已通过；正式 updater 包仍需在 CI 中注入 `TAURI_SIGNING_PRIVATE_KEY` 后发布，当前机器未配置该签名密钥。

### 6.2 增加租约端口和 relay 配置自动化测试

- 新增 `management-api/tests/test_relay_ports.py`，覆盖过期租约清理、重复端口修复、端口分配、端口占用判断和 relay 健康状态。
- 新增 `infra/relay/metering/test_metering_adapter.py`，覆盖重复端口过滤和 sing-box 配置生成。
- CI 已加入管理 API 与 relay Python 测试；本地验证结果为管理 API 4 项、relay 配置 2 项全部通过。

### 6.3 增加后台 relay 监控

- 管理 API 新增 `relay_health` 状态表和 `/v1/internal/relay/heartbeat` 心跳接口。
- relay 计量适配器每轮同步上报进程状态、监听端口、重复端口、租约数量和错误信息。
- `/v1/admin/overview` 和管理后台总览页现已展示心跳新鲜度、sing-box 进程状态、缺失端口和重复端口。
- 生产核验结果：API 容器 `healthy`，relay 进程正常运行，心跳 `process_running=1`，`duplicate_ports=[]`；有效租约端口与实际监听端口一致。

### 6.4 细化客户端诊断

- 自动问题报告新增本地代理端口、上游节点和故障类型字段。
- 客户端区分“本地端口未监听”“上游 relay 端口不可达”“SOCKS5 握手失败”“目标站点/DNS 不可达”等情况，并保留上游错误信息。
- UI 提示根据故障类型分别提示本地代理不可用或上游节点不可达，便于定位问题。
