GoYou 系统拓扑图

登录控制面、桌面端本地代理客户端、管理服务器中转节点、服务器间隧道和真实出口服务器的完整关系。

关键结论：最终用户只下载 GoYou、登录并点击“开启代理”即可。发布包需要自带本机 Shadowsocks 客户端；用户不需要另外安装 sing-box。

二、两条独立链路

控制链路：登录和授权

  1. GoYou 调用管理 API 登录。
  2. API 返回 access token、refresh token 和代理租约。
  3. GoYou 定期刷新令牌和租约。
  4. 账号到期、禁用或设备撤销后，API 停止续发租约。

数据链路：实际代理流量

  1. 浏览器、Git 或系统应用连接本机 127.0.0.1:7890。
  2. 本机客户端将 SOCKS 请求封装为 Shadowsocks。
  3. 管理服务器 relay 接收并转发到出口服务器。
  4. 出口服务器访问目标网站并返回响应。

三、用户点击“开启代理”时发生什么

1. 校验登录检查 token 和会员状态
2. 获取租约节点地址、端口、密码、过期时间
3. 启动本机客户端使用内置 sing-box 或原生实现
4. 监听本地端口确认 127.0.0.1:7890 可用
5. 开启系统代理浏览器、Git 等应用开始走代理

关闭代理时，GoYou 会停止本机客户端并恢复系统代理；不会停止远程服务器上的 relay 或 egress。

四、普通用户是否需要安装 sing-box

方式用户是否需要安装说明建议
GoYou 内置 sing-box sidecar 不需要 将 macOS/Windows 对应二进制随安装包发布，由 GoYou 启停。 第一版推荐
GoYou 内置 Rust Shadowsocks 客户端 不需要 不依赖外部进程，但需要自行实现加密、协议、DNS、IPv6 和跨平台网络细节。 后续优化
用户自行安装 sing-box 需要 只适合开发阶段验证，不适合作为正式用户体验。 仅开发环境

五、为什么不能让系统直接连接管理服务器 relay

当前 relay 对外提供的是 Shadowsocks 协议，而 macOS/Windows 的系统代理设置通常只支持普通 HTTP 或 SOCKS5，不理解 Shadowsocks。于是本机需要一个协议转换层：

系统 SOCKS5 → 本机 Shadowsocks 客户端 → 远端 Shadowsocks relay

如果未来把 relay 改成公网 SOCKS5，理论上可以取消本机客户端，但会暴露普通代理端口、增加账号滥用风险，也失去 Shadowsocks 的加密封装，因此不建议。

六、推荐落地顺序

  1. 开发阶段允许使用 Homebrew 安装 sing-box，验证登录、租约和完整链路。
  2. 为 macOS Intel、macOS Apple Silicon、Windows x64 分别准备 sing-box sidecar。
  3. 将 sidecar 加入 Tauri 的 resources，并由 Rust 根据平台选择对应文件。
  4. 发行包签名；macOS 对主应用和 sidecar 一并签名并 notarize。
  5. GoYou 首次启动只需登录，不要求用户安装任何额外软件。
  6. 后续再评估用 Rust 原生 Shadowsocks 实现替换 sidecar。
