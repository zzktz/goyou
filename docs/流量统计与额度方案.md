# GoYou 用户每日流量统计与额度方案

## 目标

- 以用户为单位统计所有设备、所有租约的上传和下载流量。
- 默认每日额度为 500 MB，后台可以为每个用户单独设置额度。
- 每日 00:00（默认 `Asia/Shanghai`）开始新的统计周期。
- 达到额度后由服务端阻断代理，客户端关闭本地代理并提示用户。

## 重要前提

客户端不能作为流量统计和限额的可信来源。当前 relay 使用所有用户共用的 Shadowsocks 凭据，无法区分用户流量；正式启用限额前必须让 relay 为每个用户或租约提供可识别的独立凭据，并由 relay 或可信计量组件上报字节数。

管理 API 的用量接口和计量上报接口先作为控制面契约实现。relay 接入后，计量组件应在 relay 侧统计流量并调用内部上报接口，不能接受客户端伪造的用量数据。

## 数据模型

### `user_quotas`

- `user_id`：用户 ID，主键
- `daily_limit_bytes`：每日额度，单位为字节
- `timezone`：统计时区，默认 `Asia/Shanghai`
- `updated_at`：最后修改时间

### `daily_usage`

- `user_id`
- `usage_date`：按统计时区计算的日期
- `upload_bytes`
- `download_bytes`
- `total_bytes`
- `last_reported_at`
- `exceeded_at`

主键为 `(user_id, usage_date)`。不删除历史记录，通过日期创建新周期。

### `usage_reports`

保存 relay 上报的 `report_id`，用于幂等去重，避免重试导致流量重复累计。

## 接口

客户端：

- `GET /v1/usage/today`：返回今日已用、额度、剩余、百分比、是否超额和下次重置时间。

管理员：

- `PATCH /v1/admin/users/{user_id}/quota`：修改单个用户每日额度。
- `GET /v1/admin/users/{user_id}/usage`：查看用户今日和历史用量。
- `GET /v1/admin/usage`：查看指定日期的用户用量汇总。

内部计量组件：

- `POST /v1/internal/usage/report`：使用独立的计量令牌上报增量流量。
- 上报必须携带唯一 `report_id`、用户 ID、租约 ID、上传增量和下载增量。
- API 对上报做幂等处理，并在事务内判断是否超额。

## 超额流程

1. relay 统计用户流量并在服务端保存本地额度缓存。
2. 达到额度时阻断新连接并关闭该用户已有连接。
3. 计量组件将超额状态上报管理 API。
4. 客户端定时读取 `/v1/usage/today`，发现超额后调用关闭代理，关闭系统代理和本地 sing-box。
5. 当日期进入下一个统计周期后，服务端自动解除当天限制。

服务端阻断是最终限制，客户端自动关闭只负责用户体验，不能替代 relay 的限制。

## 前端展示

首页显示“今日流量”卡片和进度条：已用 / 每日额度、剩余流量和重置时间。达到 80% 显示提醒，达到 100% 显示红色状态并提示代理已自动关闭。

## 规则

- 多设备、多租约按用户合并统计。
- 内部统一以字节保存，界面以 MB 展示。
- 管理员降低额度后，如果今日已用量已超过新额度，立即进入超额状态。
- 计量上报失败时 relay 使用本地缓存；缓存过期时应采用安全策略阻断，而不是允许绕过额度。
- 现有共享 Shadowsocks 凭据必须在独立凭据和计量组件上线后废弃。

## 分阶段上线

1. 上线数据库、额度配置、用量查询和客户端展示。
2. relay 接入独立用户凭据和计量上报，先观察不阻断。
3. 开启服务端超额阻断和客户端自动关闭。
4. 增加后台历史报表、设备维度和告警。
